# Criar o arquivo docs/teaching-philosophy.md

Este documento define a metodologia oficial de ensino do StudyCode.

Ele será obrigatório para qualquer conteúdo criado dentro da plataforma.

Toda aula, exercício, desafio, artigo, dica ou conteúdo deverá seguir esta filosofia.

O objetivo é garantir que todo o aplicativo mantenha o mesmo padrão de qualidade, didática e profundidade.

---

# Princípio 1

Nunca assumir que o aluno já sabe alguma coisa.

Mesmo que o assunto pareça simples, explicar desde o início.

Exemplo:

Nunca dizer apenas:

"Use let para criar uma variável."

Explicar:

• o que é uma variável

• por que ela existe

• por que precisamos guardar informações

• por que existe let

• qual problema ele resolveu

---

# Princípio 2

Todo símbolo importa.

O StudyCode deve explicar todos os elementos de um código.

Exemplo:

```javascript
if (idade >= 18) {
  console.log("Maior");
}
```

Explicar:

if

(

)

{

}

> =

.

"

;

Nada será considerado óbvio.

---

# Princípio 3

Explicar primeiro.

Memorizar depois.

O aluno deve compreender o conceito antes de decorar sintaxe.

---

# Princípio 4

Ensinar o motivo.

Nunca apenas ensinar "como fazer".

Toda aula deverá responder:

Por que isso existe?

Qual problema resolve?

Quando utilizar?

Quando não utilizar?

---

# Princípio 5

Exemplos reais.

Sempre utilizar situações do cotidiano.

Exemplos:

Login

Mercado

Banco

Restaurante

Sistema de estoque

Aplicativo de clima

Chat

Redes sociais

Projetos reais.

---

# Princípio 6

Explicar como um professor.

Nunca escrever como documentação técnica.

Nunca utilizar linguagem fria.

O aluno deve sentir que existe alguém ensinando.

---

# Princípio 7

Utilizar analogias.

Sempre que possível.

Exemplo:

Variável = caixa.

Função = receita.

Array = gaveta.

Objeto = ficha cadastral.

API = garçom levando pedidos.

Banco de dados = biblioteca.

As analogias devem facilitar o entendimento sem substituir a explicação técnica.

---

# Princípio 8

Mostrar erros comuns.

Toda aula deverá possuir uma seção chamada:

"Erros comuns."

Mostrar exatamente onde iniciantes costumam errar.

---

# Princípio 9

Criar curiosidade.

Toda aula deverá terminar com uma curiosidade.

Exemplo:

"Você sabia que JavaScript foi criado em apenas 10 dias?"

---

# Princípio 10

Aprender fazendo.

Nenhuma aula termina apenas com teoria.

Sempre possuir:

• exercício

• desafio

• mini projeto

---

# Princípio 11

A IA é um tutor.

Ela nunca deverá entregar respostas completas imediatamente.

Ela deverá:

• incentivar

• fazer perguntas

• conduzir o raciocínio

• sugerir pistas

• explicar os erros

O objetivo da IA é ensinar.

Nunca apenas resolver.

---

# Princípio 12

Construção gradual.

Toda aula deverá lembrar conteúdos anteriores.

Exemplo:

"Para entender Promise, primeiro precisamos lembrar como funcionam funções."

---

# Princípio 13

O aluno deve sair entendendo.

O sucesso de uma aula não será medido pelo tempo.

Será medido pela compreensão.

Se o aluno terminou a aula sem entender o motivo daquele recurso existir, a aula falhou.

---

# Estrutura oficial de todas as aulas

Toda aula deverá seguir exatamente esta ordem.

1. O que é?

2. Para que serve?

3. História

4. Problema que resolveu

5. Conceito

6. Sintaxe

7. Explicação símbolo por símbolo

8. Exemplo simples

9. Exemplo real

10. Erros comuns

11. Curiosidades

12. Resumo

13. Exercício

14. Desafio

15. Mini projeto

16. Próximo assunto relacionado

---

# Dicionário do Programador

Todo novo conceito criado em uma aula deverá gerar automaticamente uma entrada no Dicionário do Programador.

O objetivo é que nenhum termo técnico fique sem explicação.

---

# Regra de ouro

O aluno nunca deve sair da plataforma para entender um conceito básico.

Se existir uma dúvida sobre programação, o primeiro lugar onde ele deve procurar a resposta é dentro do próprio StudyCode.

Nosso objetivo é transformar o StudyCode na maior referência de aprendizado de programação em língua portuguesa.

---

# Filosofia Final

Não queremos que nossos alunos saibam copiar código.

Queremos que eles compreendam profundamente o funcionamento da programação.

Quando um aluno entender o "porquê", escrever código será apenas uma consequência.
