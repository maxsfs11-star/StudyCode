# Criar o arquivo docs/student-experience.md

Este documento define a experiência que queremos proporcionar aos estudantes do StudyCode.

Toda funcionalidade criada deverá respeitar esta filosofia.

Nosso objetivo não é apenas ensinar programação.

Nosso objetivo é fazer o aluno gostar de aprender programação.

Cada tela, cada aula, cada exercício e cada interação devem contribuir para uma experiência agradável, motivadora e memorável.

---

# Nossa missão

Queremos transformar o estudo de programação em uma experiência envolvente.

Aprender programação não deve ser cansativo.

Não deve ser intimidador.

Não deve parecer impossível.

O aluno deve sentir que está evoluindo todos os dias.

---

# O aluno nunca deve sentir que é incapaz

O erro faz parte do aprendizado.

O StudyCode nunca deverá ridicularizar o aluno.

Nunca utilizar mensagens negativas.

Em vez de:

"Resposta errada."

Utilizar:

"Você chegou perto."

ou

"Vamos analisar esse passo juntos."

ou

"Esse é um erro muito comum. Vamos entender por quê."

---

# Evolução constante

O aluno precisa perceber sua evolução.

Mesmo pequenas conquistas devem ser valorizadas.

Cada aula concluída deve transmitir sensação de progresso.

Nunca deixar o aluno estudar durante horas sem receber algum tipo de recompensa visual.

---

# Curiosidade acima da obrigação

O aplicativo deve despertar curiosidade.

Cada aula deve deixar o aluno com vontade de abrir a próxima.

Ao terminar uma aula, ele deve pensar:

"Agora quero descobrir o próximo assunto."

---

# Aprender deve ser divertido

Programação é difícil.

A experiência não precisa ser.

Utilizar:

• animações leves

• transições suaves

• feedback positivo

• ilustrações quando necessário

• gráficos

• fluxogramas

• exemplos visuais

Tudo deve facilitar a aprendizagem.

Nunca distrair o aluno.

---

# Interface limpa

O conteúdo é o protagonista.

Evitar excesso de elementos.

Evitar excesso de cores.

Evitar distrações.

Toda tela deve direcionar o foco para o aprendizado.

---

# Desafios

Os desafios devem evoluir gradualmente.

Nunca frustrar o aluno.

Nunca criar desafios impossíveis.

Cada desafio deve aumentar um pouco a dificuldade.

---

# Exercícios

O objetivo não é apenas acertar.

O objetivo é compreender.

Mesmo quando o aluno errar, ele deve aprender algo novo.

---

# IA

A IA não é um mecanismo para entregar respostas.

Ela é um tutor.

Ela deve incentivar o aluno a pensar.

Ela deve fazer perguntas.

Ela deve oferecer dicas.

Ela deve conduzir o raciocínio.

Ela nunca deverá substituir o aprendizado.

---

# Motivação

O aluno deve sentir orgulho da própria evolução.

Mostrar:

XP

Conquistas

Sequência diária

Projetos concluídos

Horas estudadas

Novas habilidades desbloqueadas

Tudo isso deve reforçar a sensação de crescimento.

---

# Linguagem

Toda comunicação do aplicativo deverá ser:

amigável

respeitosa

motivadora

didática

profissional

Nunca utilizar mensagens agressivas.

Nunca culpar o aluno pelos erros.

---

# Dificuldade

A dificuldade deve aumentar de forma gradual.

Nunca apresentar conceitos avançados antes da base.

Sempre construir conhecimento passo a passo.

---

# Aprender fazendo

O aluno aprende escrevendo código.

Sempre incentivar prática.

Sempre incentivar experimentação.

Sempre incentivar curiosidade.

---

# Aulas

As aulas devem parecer uma conversa com um excelente professor.

Nunca apenas uma documentação.

Nunca apenas texto.

Sempre ensinar.

Sempre demonstrar.

Sempre explicar.

---

# Sensação ao terminar uma aula

Ao concluir uma aula, queremos que o aluno pense:

"Agora eu realmente entendi."

e não

"Agora eu decorei."

---

# Nosso maior objetivo

Não queremos que o aluno apenas conclua cursos.

Queremos que ele ganhe confiança para abrir um editor de código e desenvolver seus próprios projetos.

O verdadeiro sucesso do StudyCode acontece quando o aluno deixa de depender da plataforma para resolver problemas simples.

Isso significa que cumprimos nossa missão.

---

# Filosofia Final

O StudyCode existe para formar desenvolvedores.

Não apenas para ensinar linguagens.

Toda decisão de design, conteúdo ou tecnologia deve responder a uma única pergunta:

"Isto torna a experiência de aprender programação melhor para o estudante?"

Se a resposta for não, a funcionalidade deverá ser repensada.
