# Criar o arquivo docs/content-quality.md

Este documento define o padrão oficial de qualidade do conteúdo do StudyCode.

Nenhuma aula, artigo, exercício ou material poderá ser publicado sem atender aos critérios definidos neste documento.

O objetivo é garantir que toda experiência de aprendizado dentro do StudyCode mantenha um padrão elevado de qualidade.

---

# Missão

Todo conteúdo do StudyCode deve ensinar programação de forma clara, profunda, didática e profissional.

Nosso compromisso não é criar muitas aulas.

Nosso compromisso é criar as melhores aulas possíveis.

Preferimos possuir menos conteúdo com excelente qualidade do que centenas de aulas superficiais.

---

# Clareza

Todo texto deve ser fácil de entender.

Evitar palavras difíceis quando uma explicação simples resolver.

Quando utilizar um termo técnico, explicar seu significado.

Nunca assumir que o aluno já conhece determinada palavra.

---

# Profundidade

Nenhum conteúdo deverá explicar apenas "como fazer".

Todo conteúdo deve explicar:

• o que é

• para que serve

• por que existe

• quando utilizar

• quando não utilizar

• vantagens

• limitações

• erros comuns

• aplicações reais

---

# Conteúdo Original

Todo material deverá ser escrito pelo próprio StudyCode.

Nunca copiar textos da internet.

Nunca copiar documentação oficial.

Nunca copiar exemplos de outros sites.

Utilizar documentações oficiais apenas como referência técnica.

Todo texto deverá possuir identidade própria.

---

# Exemplos

Todo conceito deverá possuir exemplos.

Os exemplos deverão seguir esta ordem:

1. exemplo extremamente simples

2. exemplo intermediário

3. exemplo utilizado em projetos reais

Sempre mostrar o código funcionando.

Nunca utilizar exemplos excessivamente complexos para iniciantes.

---

# Código

Todo código publicado deverá:

• funcionar

• ser legível

• possuir boa identação

• utilizar boas práticas

• possuir nomes claros

Evitar códigos confusos.

Evitar abreviações desnecessárias.

---

# Explicações

Explicar o código linha por linha.

Sempre que necessário, explicar palavra por palavra.

Sempre explicar símbolos.

Exemplos:

;

()

{}

[]

.

,

=>

===

&&

||

!

??

...

Nada deve ser considerado óbvio.

---

# Atualização

O conteúdo deverá acompanhar a evolução das linguagens.

Quando houver mudanças importantes:

• revisar aulas

• atualizar exemplos

• atualizar boas práticas

• marcar conteúdos descontinuados

Nunca deixar aulas ensinando práticas ultrapassadas sem aviso.

---

# Exercícios

Todo exercício deve possuir um objetivo claro.

Não criar exercícios apenas para ocupar espaço.

Cada exercício deverá reforçar o conceito estudado.

---

# Desafios

Os desafios devem estimular o raciocínio.

Evitar exercícios de copiar e colar.

O aluno deve pensar antes de escrever.

---

# Mini Projetos

Sempre que possível, finalizar um conjunto de aulas com um pequeno projeto.

O aluno aprende muito mais quando utiliza vários conceitos juntos.

---

# IA

A IA deverá incentivar o aprendizado.

Nunca entregar imediatamente uma solução completa.

Ela deverá:

• analisar o erro

• explicar o motivo

• sugerir melhorias

• incentivar tentativa

• fazer perguntas

• conduzir o raciocínio

A IA existe para ensinar.

Não para substituir o esforço do aluno.

---

# Dicionário do Programador

Sempre que surgir um novo termo técnico:

Criar uma entrada correspondente no Dicionário do Programador.

Nenhum conceito importante deverá ficar sem documentação.

---

# Curiosidades

Sempre que possível, adicionar curiosidades relacionadas ao assunto.

Exemplos:

História.

Criadores.

Origem.

Mudanças importantes.

Comparações.

Casos reais.

As curiosidades tornam o aprendizado mais interessante.

---

# Referências

Utilizar como referência:

• documentação oficial

• especificações oficiais

• boas práticas

• materiais reconhecidos pela comunidade

Nunca utilizar fontes duvidosas.

---

# Revisão

Antes da publicação, toda aula deverá responder:

O aluno realmente entenderá este assunto?

Existe algum conceito que ficou sem explicação?

Os exemplos fazem sentido?

O conteúdo possui erros?

Os exercícios reforçam o aprendizado?

A IA conseguirá auxiliar corretamente nesta aula?

---

# Regra de Ouro

Se existir uma forma melhor de explicar um conceito, ela deverá ser utilizada.

Nosso objetivo não é apenas ensinar programação.

Nosso objetivo é fazer o aluno compreender programação profundamente.

Toda aula publicada deve ser motivo de orgulho para a equipe do StudyCode.

Qualidade sempre estará acima da quantidade.
